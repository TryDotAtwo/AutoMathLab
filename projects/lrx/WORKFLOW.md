# Работа по карте доказательства

1. `proof-map.json` хранит одно текущее состояние обязательства. Issues хранят обсуждение, принятие и handoff; доказательства и review остаются отдельными версионированными файлами. ROADMAP/KANBAN/HTML — только производные.
2. Пакет связан с узлом и точным критерием приёмки. Предложение ≠ принятие; owner означает ответственного за следующий шаг, assignment показывает подтверждение. После текущего пакета не запускайте новый до согласования с исполнителем. Для независимых проектов принятие добровольное.
3. Переходы: backlog → working → review → integration → done. blocked содержит причину и следующий шаг. Закрывается точное утверждение пакета, не автоматически общая теорема. Claim, verification и publication учитываются раздельно.
4. Перед новым пакетом/сводкой тимлид читает карту и только новые события. Привязывает артефакт к узлу, проверку — к версии, назначает reviewer и интегратора. Если runtime не наблюдается, пишет unknown; старое ACK не доказывает активность. Просроченный checkpoint требует проверки, а не остановки чужого процесса.
5. Тимлид обновляет собственный persistent checkout и генерирует карту. При отсутствии GitHub write сохраняет patch/handoff координатору; не утверждает публичную синхронизацию. Публичная версия считается обновлённой только после подтверждённого commit/PR/merge. Не заводить вторую независимую карту статусов.
6. Основной путь и альтернативы разделены. ALT-C не обязательная зависимость EQ; заменить узлы основного пути можно лишь после проверки совместимости. Финитные тесты не доказывают все n. Условное Valid→realize не закрывает PLAN.
7. Исторические записи остаются в Git и прежних журналах. Текущие файлы должны оставаться короткими; не наращивать в них ленту сообщений. Публично — существенный результат, ответ на вопрос или редкая сводка; технические логи отдельно.

Проверка/генерация из корня: `python3 scripts/render_lrx_map.py`; CI/контроль: `python3 scripts/render_lrx_map.py --check`. Обновление только stdlib Python, без LLM и сетевых запросов. Изменение JSON без регенерации считается рассогласованием.

Реестр, шаблон и производные представления используют UTF-8; `.gitattributes` фиксирует для них LF, чтобы SHA-256 реестра совпадал и в Windows checkout с `core.autocrlf=true`. Генератор записывает UTF-8/LF явно. Проверки не отключаются флагом Python `-O`. Эти правила не нормализуют архивные исходники или журналы с уже опубликованными хешами.

## Схема 2: подтверждения и область утверждения

`verification` — объект с полями `status`, `coverage`, `notes`, `record`.
Статусы соответствуют CONTRIBUTING.md: `not-reviewed`, `author-checked`,
`independently-reproduced`, `formally-checked`. `coverage` равно `none`, `partial`
или `full` и относится к **точной формулировке узла**. Оговорки о частичном
replay сохраняются в `notes`; наличие Lean-проверки отдельной леммы не даёт
`full` всему узлу. `not-reviewed` требует `coverage=none`.

Для `done` нужны `claim=proved`, `coverage=full`, статус
`independently-reproduced` либо `formally-checked` и запись `record`:

```json
{
  "statement": "Точная строка statement этого узла, включая условия",
  "reviewer": "Автор проверки и границы её независимости",
  "artifact": {"url": "https://host/path/to/artifact", "revision": "sha256:<64 hex digits>"},
  "review": {"url": "https://host/path/to/review", "revision": "sha256:<64 hex digits>"}
}
```

Это форма записи; плейсхолдеры не проходят валидацию. Разрешены полный SHA-256
либо `git:<40 hex digits>`; для Git URL должен указывать тот же commit через
`/blob/<commit>/`, `/tree/<commit>/` или `/commit/<commit>`. Обе ссылки также
перечисляются в `evidence`. Изменение `statement` требует обновить связанную
запись проверки. `formally-checked` может ссылаться на авторский kernel receipt;
это само по себе не означает независимый replay или человеческую рецензию.

В миграции версии `2026-09-26.3-schema2` все прежние `state`, `claim`,
`statement`, назначения и научный cutoff 10:35 UTC сохранены. Прежние строки
проверки перенесены целиком в `notes`; scoped-проверки имеют `coverage=partial`.
Для существующих `D` и `LIFT` добавлены закреплённые публичные материалы PR5
и PR7. Запись LIFT ссылается именно на исходную авторскую Lean-проверку;
существующая ссылка на последующий независимый replay остаётся в evidence.
Эта миграция не повторяет Lean-сборку и не освежает научный снимок.

## Зависимости и альтернативный маршрут

`proof_scope` равен `unconditional` или `conditional`. Для conditional поле
`assumptions` явно перечисляет сохраняемые предпосылки; для unconditional оно
пустое. EXEC формулирует условную теорему о предъявленном допустимом плане.
Узлы `U-ALL` и `EQ` всегда unconditional.

`requires` сохраняет основной путь. `dependency_kinds` содержит ровно те же
ID: `assumption-discharge` означает, что готовность требует `done` этого узла;
`build` отмечает связь с исходниками/сборкой и не доказывает предпосылку.
Build-only связь допустима только у явно условного узла. Это позволяет закончить
Valid→realize до общего конструктора, но не позволяет скрыть незакрытые
предпосылки U-ALL за сборочными зависимостями. Валидатор проверяет каждый done,
а не цветовую группу `strategy`; циклы запрещены и в основном, и в выбранном DAG.

Для проверенной альтернативы у потребителя добавляется `route_selection`:

```json
{
  "route": "alternative",
  "via": "ALT-C",
  "replaces": ["BRIDGE", "PLAN", "COST"],
  "review": "Здесь нужна запись формы record выше, не строка"
}
```

Это пример структуры, не готовая запись и не действующая замена в текущем
реестре. `review.statement` должен совпадать с формулировкой потребителя;
review подтверждает совместимость версии альтернативы с этим интерфейсом.
Заменять можно только зависимости из `routes[].replaces_when_proved`.
Остальные зависимости сохраняются; `via` добавляется с типом `route-selection`
и тоже должен быть done при готовом потребителе. Исходные рёбра не удаляются.
Непроверенная или незавершённая альтернатива не закрывает теорему. Проверенный
выбранный маршрут не требует готовности уже заменённых узлов основного пути.

## Что проверяет команда

Разрешены HTTPS без credentials и относительные ссылки на файлы внутри
репозитория; управляющие символы, пробелы, обратные слэши, protocol-relative URL
и другие схемы отклоняются. HTML дополнительно проверяет href перед вставкой.
Неизвестные claim/verification, неверные типы и пустые обязательные строки
отклоняются. `python3 -m unittest discover -s tests -p 'test_lrx_map.py'`
проверяет отрицательные и положительные сценарии, включая Windows и `-O`.

PASS подтверждает структуру метаданных, форму закреплённых ссылок, выбранные
зависимости и синхронность представлений. Команда не скачивает артефакты,
не проверяет фактические хеши удалённых файлов, доступность ссылок,
подлинность review или истинность математических утверждений. За это отвечает
отдельная научная проверка указанной версии. Синтаксически корректная выдуманная
запись не становится доказательством после PASS.

На каждом контрольном проходе: прочитать текущую версию → сверить новые артефакты/принятия → обновить только подтверждённые поля → проверить зависимости → передать reviewer/интегратору → предложить следующий незанятый пакет. Не создавать новый диалог на сообщение и не дублировать активные вычисления.
